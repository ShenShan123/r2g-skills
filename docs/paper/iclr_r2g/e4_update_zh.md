## 主张的变化

旧叙事强调“文件齐全仍不合格”，而新 GPT 已通过全部身份与拓扑检查。现在更有力且准确的论点是：**拓扑正确只是转图的一部分，合格的数据产品还必须把物理数值与标签关联到正确实体，并遵守阶段与有效性契约。**

因此正文不再沿用旧 400k 成绩、4/3/3 轮开发、97.4/100/100% 静态覆盖，也不再把旧版 GPT 的身份失败或 Claude/Qwen 的空图/固定占位诊断当作本轮表现。

## 正文如何突出 R2G

- 摘要和引言：加入“完美拓扑与不完整物理监督可以同时出现”的实测对照。
- 方法：补充 native Yosys 身份解析、按实体键装配、DEF/SPEF/STA 物理量提取与有效性传播，解释转图的具体技术内容。
- 图 4：用两组横向条形图区分身份/拓扑 F1 与数值/标签正确覆盖，不再使用旧静态包装图。
- 案例表：同一 blinking 中 R2G/GPT 均匹配 211 门、644 pin；R2G 匹配 209/209 线长、207/207 ground cap、27/27 setup 和 27/27 hold。GPT 对应正确数为 178/209、100/207、0/27、0/27。
- 案例诊断：GPT 的 slack 正则匹配顺序及寄存器实例到 pin 的映射缺口，与原始 STA 文本和审计缺失相对应。Claude/Qwen 的漏实体、schema 与初始化问题依据本轮程序，不引用旧版错误解释新版。
- 附录：保存完整三态语义图、精确成绩和 400k→600k **开发集**轨迹；旧 400k 快照未重新测试，不能画成测试集预算收益。

## 保留的科学边界

这是固定 24 题复测，不是新隐藏队列。开发只获得六题反馈、测试阶段无 API 调用；不将请求任务 ID 检查夸大成全面无泄漏证明。原早期协议曾计划新队列，最终以 readiness 和最终报告的 fixed benchmark retest 为准。

论文强调 R2G 交付了完整的已审计数据接口，不声称独一无二、LLM 已到能力上限、全部特征形式化正确或已经带来下游精度收益。识别错误与连带拓扑缺失不是两种独立根因；U 保留为不可评估，未转写成数值已经算错。

E1/E3 数字不变；后续视觉修订统一了图表配色与完整模型名称。旧实验四的 1,473.585 秒不用于新复测，避免混用运行成本。历史异常保留为早期 campaign 记录，不误写为本轮新发生的问题。

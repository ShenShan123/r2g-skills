This is a working companion to the R2G manuscript, not a completed experimental report or a submission supplement. Every TBD cell is unmeasured. \section{E5: End-to-End Usable Dataset Yield}
\textbf{Question.} Does R2G increase the number of independently usable learning samples obtained from a fixed source cohort?

\textbf{Protocol.} Freeze a new repository/family-disjoint cohort before observing downstream outcomes. Use the same source inventory, target clock, platform, resource budget, and toolchain for all methods. Record every design's terminal state. Compare default ORFS, a fixed expert-rule pipeline, and R2G; add a constrained ORFS-agent implementation if feasible. Separate a prescribed-source integration experiment from open-ended acquisition: only the latter can measure source-discovery effects.

\textbf{Endpoint.} A sample must meet source eligibility, frozen physical checks, complete required stage artifacts, core semantic acceptance, and the training-interface smoke test. Report $N_{\rm usable}/N_{\rm initial}$ and conditional stage rates. Infrastructure-inconclusive cases retain separate status; state both the all-launched denominator and any justified sensitivity analysis. No silent deletion of hard designs is allowed.

\section{E6: Strong Conversion Baselines}
\textbf{Question.} Are improvements attributable to semantic handling rather than interface completeness or transport failures?

\textbf{Protocol.} Build a native Yosys/OpenDB baseline or a CircuitOps adapter for the intersection of supported identity, connectivity, coordinate, and physical-label fields. Judge this common semantic subset separately from full R2G packaging. An unsupported field is N/A for the intersection comparison, not an automatic baseline failure. Retain full-contract usability as a separate product-level endpoint. Record adapter implementation effort and code hashes. Use development data only to implement adapters and repair the common-subset evaluator.

Repeat at least the strongest LLM baseline using stable service, with a predeclared number of completed development responses and separate transport retry rules. Freeze token and EDA ceilings, provider usage accounting, source APIs, and model route. Any fallback or budget change creates a new protocol. Use new hidden designs after development; do not tune on E4's now-exposed hidden set. If only one development seed is affordable, label the study a single-program replication; prefer three independent development seeds when feasible.

\section{E7: Downstream Prediction Utility}
\textbf{Question.} Do the constructed graphs support useful prediction under actual deployment cutoffs?

\textbf{Protocol.} Begin with route wirelength per canonical net and setup slack per independently reportable pin. Freeze train/validation/test groups by repository and RTL lineage; all stage views and parameter variants of a design stay in one split. Prefer three independent design splits and three training seeds if budget allows; at minimum use one fixed split with three seeds and acknowledge that it does not measure split uncertainty. Use only train-fitted normalization. Remove graph IDs, names, paths, target-derived topology, and supervision relations from encoder inputs. Missing features use declared masks with train-only preprocessing. Freeze target transforms and evaluation in physical units.

Compare train-set constant prediction, an MLP on the same available features, a graph model on logical connectivity, and the same model with permitted physical features. To test construction quality, compare R2G and a common-contract baseline on identical samples with identical models. A claim of increased useful data requires a separate equal-size/equal-origin comparison and a full-yield comparison; otherwise dataset size and quality are confounded.

\section{E8: Repair Mechanisms and Broader Transfer}
\textbf{Question.} Does evidence-based promotion improve decisions beyond a small fixed rule library?

Construct a new B2 cohort stratified by independent failure mechanisms, not merely new names exhibiting \texttt{m3.2}. Include setup cases diagnosed by synthesis mapping, placement delay, fanout/buffering, and constraint interpretation where the fixed action policy can plausibly help. Audit feasibility before freezing without reading method outcomes; retain unsuccessful cases in the denominator. No clock relaxation counts as repair.

Compare M0--M3, fixed expert recipes, a random ordering of the same admitted bank, and a policy-constrained ORFS-agent if available. A retrieval-only LLM using exactly the same frozen A evidence isolates inference from access to prior knowledge. Exposed B data may support future development but cannot remain the test set. Separate recipe coverage, top-1 success, top-3 success, trial cost, and sentinel regression. Sweep promotion thresholds only on validation data, then freeze one operating point.

\textbf{Amortization.} Report total learning cost $C_A$ separately from deployment cost $C_B(n)$ and the baseline cost $C_L(n)$. Compare $C_A+C_B(n)$ with $C_L(n)$ at matched useful outcomes. \section{E9: Semantic Mutations and Noninterference}
\textbf{Question.} Can independent checks detect plausible silent corruption, and do early inputs remain unchanged when future information changes?

Freeze mutation families before evaluation: net/pin identity permutation; unit scaling; invalid-mask inversion; hierarchy and bus-name perturbation; altered split-net aggregation; later-stage coordinates copied into an earlier view; RC/timing supervision relations enabled as encoder inputs; missing timing endpoints. Each mutation should preserve enough packaging to test semantics. Include equivalent benign transformations and untouched controls. Report per-family detection, false alarms, and unassessable rates. An audit that always rejects does not establish useful detection.

For noninterference, hold allowed early inputs fixed and change or withhold only future-stage files. Compare canonical topology, early features, encoder relation sets, and preprocessing outputs. Shared target labels may legitimately change; do not require the whole serialized graph hash to remain constant. Enforce file access through an instrumented runner and audit training inputs as well as converter metadata.

\section{Optional E10: Technology and Scale Transfer}
Validate tool and rule availability before selecting another platform. Candidate choices include Nangate45 or IHP SG13G2 if the actual frozen flow supports the required checks. The current signoff-loop explicitly does not support ASAP7 as an ordinary strict-signoff platform; do not select it merely because prior papers use it. A few engineering smoke cases establish portability only, not broad generalization.

\section{E11: Strict-Corpus Admission Under Faulty Evidence}
\textbf{Question.} Does the publication boundary reject physically or provenance-ineligible outputs while retaining eligible controls?

Freeze copies of independently judged eligible cases. Introduce one fault at a time: remove a required DRC/LVS report, replace it with a report from another run, change a source artifact while preserving its filename, corrupt a reused-stage digest, remove a parent lineage record, inject a dirty route verdict, or supply a caveated result to the strict profile. Include unchanged positive controls and correctly declared research-profile cases. Test the actual corpus index/publication boundary, not only a helper's exit code. Gate-off mutations must use an isolated test index and never enter the real corpus.

This tests admission correctness, whereas E9 tests graph-value semantics and feature availability.

\section{E12: Continual Production and Policy Evolution}
\textbf{Question.} Does past evidence improve useful production on later independent designs at acceptable total cost?

Freeze a chronological stream of repository/family-disjoint windows. Compare a fixed scripted pipeline, the initial frozen policy, and evidence-gated updates with identical candidate order and budgets. At each boundary, freeze the policy using past windows only; evaluate it on the next window before permitting that window's outcomes to inform a subsequent update. Retain a final untouched window. Log static-bootstrap rules separately from learned recipes. Match evaluation subjects across policies and report drift in design size and failure mix.

Measure cumulative usable graphs, unique qualified design families, failed/rejected/escalated counts, interventions, restart work, promotion/demotion events, and learning-inclusive EDA and token cost. To isolate recovery, ablate adaptive diagnosis, history retrieval, and controlled promotion separately where feasible. Raw production-rate increases across time can reflect an easier candidate mix; paired policies on the same windows address this confound. E3 alone cannot fill this table. If no such experiment is completed, retain frozen-transfer claims and omit claims of measured continual self-improvement.

\section{Reproducibility Fields}
For each new experiment retain: protocol version and pre-run hash; sample/family IDs and split hashes; source revisions; tool and platform versions; model routing and usage provenance; runtime and memory limits; candidate/converter hashes; all terminal outcomes; intermediate metrics; intervention/retry logs; and evaluator version. Add a claim-to-artifact row before moving any TBD result into the main paper. This companion is a design proposal, not evidence that the experiments have been executed.

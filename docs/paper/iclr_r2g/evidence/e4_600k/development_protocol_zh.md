# 实验四补充实验：真实数据优先的增量开发

状态：独立补充实验。保留既有正式成绩；本实验不直接覆盖论文旧表。

## 固定条件

- 三个模型从空程序开始；不复制旧转换器，不提供测试案例的根因或修复代码。
- 沿用六个开发设计；旧测试设计全部排除出新测试候选。新测试暂未选定，在确认来源、仓库与近重复隔离前不运行最终测试。
- 经用户确认，在独立测试开始前统一追加一次开发预算：每模型累计有效 Token 上限为 600000，最多 18 次响应，每次输出最多 16384 Token。原 400000 / 12 次阶段的结果保存于 `budget_extension_600k/before`；沿用已有代码、反馈和累计消耗，不从零重跑。达到新上限后停止，不因测试成绩继续追加预算。
- 支持原生 Yosys/OpenROAD 子进程，使用相同工具链。转换程序无网络，仅能读取本题配置列出的输入、安装环境和工具链，不能读取 R2G 源码或其他题目产物。
- 初始只开一个模型开发 worker；每题最多 3600 秒。此处不是重新跑物理实现，只转换既有输入并评分。

## 开发反馈与选优

1. 真实 gate/pin/net/I/O 身份覆盖及 precision/recall/F1。
2. 真实核心连接的 precision/recall/F1。
3. 物理标签/坐标的期望覆盖、已匹配数值误差和缺失数量。
4. 阶段一致性、因果截止点与完整包装契约。

每轮均检查全部六个开发设计，不人为藏起后续错误。选优按完整语义通过数、身份 F1、拓扑 F1、标签正确覆盖、数值正确覆盖、静态覆盖的字典序；同分选较早轮。空图不会因 mask/对齐内部一致而获得实体覆盖分。

增量编辑采用唯一精确匹配的 old/new 替换；任何编辑歧义或语法错误都保留上个程序，并把错误反馈给模型，不抹掉历史。每个响应先保存内容和 usage，再转换、评分；中断后复用响应，不重复请求。无 usage 的请求按保守估计记账，无法知道的网络调用实际费用单独保留。

## 结果边界

开发集用于修改；新测试集只在程序选定后运行。若日后使用旧测试诊断直接提示模型，必须另记探索运行，不与本方案混用。七类检查不代表七种独立根因；最终报告同时给整体可用数和分项覆盖/误差，不把不可评估当作已证实数值错误。

## 准备测试

先验证动态契约、原子编辑、空图计分与 oracle 故障隔离；再使用开发集上的旧转换程序做非计分基础设施 canary。这些旧代码只供测试 runner，不作为三个新模型的初始代码。canary 未通过不花费新模型预算。

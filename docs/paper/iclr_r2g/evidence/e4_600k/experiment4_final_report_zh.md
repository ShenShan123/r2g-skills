# 实验四：60 万 Token 预算下的固定基准复测

## 实验设计与状态

本轮开发及评分已经完成。GPT、Claude、Qwen 从空程序开始，在同一组 6 个开发设计上获得语义反馈并进行增量编辑，允许调用原生 Yosys/OpenROAD。预算从每模型累计 40 万统一追加至 60 万 Token，最多 18 次响应，每次最多输出 16384 Token。已有响应和消耗累计保留，不因续跑清零。

开发完成后选定转换器，在原固定 24 个测试设计上复测，R2G 和三个模型采用相同输入、工具链及评分器。共完成 96 个方法×设计的转换、常规评分和语义审计。测试阶段无模型 API 调用，不再根据测试结果修改程序。

这不是全新未接触测试集。请求检查未发现固定测试题的任务标识，结构化开发反馈仅来自 6 个开发设计；这种检查不等于证明不存在一切形式的先验接触。输入与选定代码的哈希绑定见随附 readiness.json。

## 结论及边界

结果支持：在给定开发预算和工具接口下，生成转换器能够实现部分真实图结构，但完整物理数值、标签和阶段契约仍存在缺口；R2G 在本轮核心审计范围内达到 24/24。GPT 的身份和拓扑已全部通过，不应写成 LLM 不会建图。

不能据此声称模型达到绝对能力上限，或 R2G 具有独一无二、不可替代的能力。R2G 是长期开发的软件，其开发成本不与本轮 LLM 预算等同。未全面验证的范围包括全部 Liberty 特征、引脚形状/层几何、拆分重命名网络部分物理标签、RC/时序边标签、拥塞值、执行级非干扰及批量训练。

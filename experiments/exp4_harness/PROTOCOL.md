# 实验 4.4.1：数据集生产中的 harness 验证

正式运行协议；运行状态见 STATUS.md，主表在全部结果收集后填写。

本实验只回答一个问题：对于相同模型，R2G 能否比其原生 harness 更准确、更省资源地生产可用的图数据集？实验三仍是主实验；这里用一张四行表做补充验证。

| 模型 | 原生组 | R2G 组 |
| --- | --- | --- |
| DeepSeek Flash | DeepSeek Harness 0.2.2-rc.1 | R2G agent loop + def-graph skill |
| GPT-6.1-sol | Codex CLI 0.169.0 | R2G agent loop + def-graph skill |

实际模型 ID、响应模型、harness 版本和请求参数随日志保存。DeepSeek 两组使用相同 Messages 端点、thinking/high；GPT 两组使用相同 Responses 端点、medium。每次最多 200 个模型请求、4 小时开发、8 核、32 GiB 内存；每个测试设计最多 30 分钟。所有模型请求，包括原生子代理及重试，都经过同一计量网关。

四组同时启动，每组使用不重叠的 8 个逻辑核，各自依次完成 3 次独立重复。开发、生产和评分的 `/tmp` 均使用独立磁盘目录，不设原来的 8 GiB tmpfs 容量限制。2026-11-15 首次两路运行因该临时空间限制归档为预运行；正式结果来自新的四路运行目录，不混入旧结果。服务器与其他任务共享，记录实际耗时。

2026-11-15 迁移：正式四组统一在 memlab203 的 CPU 上从新会话运行，216 上的启动记录保留为预运行。203 使用 Bubblewrap 0.6.1 挂载同一固定 OCI 镜像导出的只读文件系统，隔离网络、PID、用户等命名空间，四组保持相同运行环境。未挂载 GPU；模型推理由远程 API 提供。开发和生产的大文件按单元流式归档至 216，经两端 SHA-256 一致校验后释放 203 副本。评分、日志和冻结转换程序保留，归档等待不计入生产耗时。

## 样本与一次运行

从已有完成物理实现的设计中固定选择 Nangate45、SKY130HD、GF180 三种工艺。开发集每种工艺 6 个，小/中/大各 2 个，共 18 个。测试集每种工艺 20 个，小/中/大为 6/8/6，共 60 个。规模优先按 300–999、1,000–10,000、10,001–30,000 个单元划分；最终清单、规模阈值和来源记录在 cohort.json。选择只使用来源、工艺、规模、输入完整性和原有 signoff 状态，不查看转换结果。

开发集与测试集按源仓库家族隔离，隔离跨越工艺；同一源设计不同工艺不能跨开发/测试。最终选择包含 18 个开发家族和 60 个测试家族。两集均排除旧实验四出现过的候选设计标识，17/78 个设计所属的仓库曾在旧实验出现，已在清单记录。

四组各独立开发 3 次：每次使用新的会话和目录，从相同的 18 个开发设计准备一套通用转换程序。提交后冻结代码，将同一程序依次应用到全部 60 个测试设计。测试期间不调用模型、不修补代码、不返回测试评分。缺少程序或输出同样占据测试分母。

## 输入、产物与隔离

输入为最终 DEF、SPEF、SDC、网表、设计配置及工艺 LEF/Liberty。产物为 B–F 五种图的 homogeneous / heterogeneous 两种表示，共十个 PyG 文件；只评价非功耗部分的特征、连通关系与标签。图像和四阶段图不在本次验证内。

原生组得到格式规范、公开格式检查器、相同开发数据以及 Python/PyTorch/PyG/OpenROAD 工具，自己编写转换脚本。容器不挂载 R2G 源码、转换脚本、独立答案或其他组工作区。R2G 组额外挂载冻结的 def-graph skill 和既有转换实现。真实 R2G agent loop 用数据集专用 shell 工具驱动开发，不重跑 RTL 物理实现、不使用作业回放。这个设置比较包括成熟转换实现的 R2G 整体机制。

格式检查器供两组开发时使用，只检查文件、张量和表示一致性；独立物理答案及评分器在另一容器内运行。参考答案从同一最终 DEF/SPEF/SDC、LEF/Liberty 独立抽取。数值容差在首次正式运行前固定在 scoring.py。

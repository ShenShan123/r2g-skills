# 实验 4.4.1：Image 数据集生产中的 harness 验证

Image 与 Graph 为并列验证任务，保持同等样本量、重复次数和资源预算。这里验证模型驱动的 harness 能否准确、低成本地生成可供视觉模型使用的布局特征与拥塞标签；实验三仍是主实验。

## 四组与样本

| 模型 | 原生 harness | R2G harness |
| --- | --- | --- |
| DeepSeek Flash | DSH 0.2.2-rc.1 | R2G agent loop + def-graph image 能力 |
| GPT-6.1-sol | Codex CLI 0.169.0 | R2G agent loop + def-graph image 能力 |

沿用 Graph 的 78 个设计身份和开发／测试划分：Nangate45、SKY130HD、GF180 各 6 个开发设计、20 个测试设计，共 18 / 60 个，覆盖小、中、大规模。源仓库家族跨工艺隔离，两组身份清单不相交。每组独立开发 3 次，每次冻结一套通用转换程序，再盲测全部 60 个设计；测试阶段不调用模型修补。共 12 次开发、720 次测试转换。

SKY130HD/GF180 使用原运行保留的 placement ODB 导出的 DEF 与原 final DEF。Nangate45 的旧归档没有 placement 数据，因此使用原配置、约束及固定工具镜像重跑完整物理流程，保留同次运行的 placement/final 文件对；记录与原 final 的哈希对比，不把新运行记为已重新 signoff。四组共享完全相同的这些输入。此公共输入准备不计入任何 harness 的转换成本。

## 任务与隔离

输入为 `3_place.def`、`6_final.def`、设计配置和各工艺 LEF/Liberty。产物为 `features.npz` 的五个布局特征通道（cell density、macro region、RUDY、pin RUDY、pin density），以及 `labels.npz` 的原始／平滑拥塞图。前者读取布线前 placement，后者读取布线后 final，共用物理 GCell 网格。这是数值训练样本；PNG 仅用于展示。

原生组获得公开数学定义、格式检查器、原始开发数据和标准 Python/OpenROAD 工具，自己编写转换器；不挂载 R2G 源码或脚本。R2G 组使用真实 agent loop，额外挂载冻结的 `def-graph` image 实现。R2G 专用入口组合已有拥塞提取、图像构建及验证器，仅执行本任务需要的步骤。全部组的隐藏参考答案由独立 DEF/LEF 解析与栅格计算产生，开发时不可见。

## 准确率与成本

完整正确要求程序成功退出、格式正确，并且七个数组的每个像素都满足预先固定的逐像素数值容差。像素准确率对五个特征加原始拥塞这六个独立通道中的非空参考通道等权平均，再对 60 个设计等权平均；全零通道仍须完全正确，平滑拥塞也必须通过，二者不重复抬高主像素指标。缺输出和运行失败计错。具体公式与容差见 [SEMANTICS.md](SEMANTICS.md)。

每次开发最多 200 次模型请求、4 小时、8 核、32 GiB；每个测试设计最多 30 分钟。模型、推理参数、API 网关及 Token 口径与 Graph 相同，含重试及原生子代理。总 Token 为输入（含缓存读取）加输出；总耗时为开发加 60 次生产的实测时长，排除独立评分、公共数据准备、排队和归档等待。生产 CPU 时间及开发／生产峰值内存另存附件。

四组在 203 上同时运行，使用互不重叠、且与 Graph 不重叠的物理核心。大文件校验后归档至 216。冻结前完成三工艺开发样本预检、四组真实模型／工具调用预检和原生挂载隔离检查。预检不计入正式结果。

## 简洁呈现

| 模型 × harness | 完全正确设计 / 60 ↑ | 像素准确率 ↑ | 总 Token ↓ | 总耗时 ↓ |
| --- | --- | --- | --- | --- |
| DeepSeek × 原生 | 待测 | 待测 | 待测 | 待测 |
| DeepSeek × R2G | 待测 | 待测 | 待测 | 待测 |
| GPT × 原生 | 待测 | 待测 | 待测 | 待测 |
| GPT × R2G | 待测 | 待测 | 待测 | 待测 |

每格报告三次独立开发的均值与范围，与 Graph 表并列。另用预先选定的一个中规模设计展示 cell density、RUDY、参考拥塞及四组误差图；各组使用同一色标，展示第一轮结果，不按差距挑案例。样例身份记录在 `presentation.json`。

重点检验 R2G 是否降低开发成本、提高完整样本通过率，并同时报告批量生产成本。若两者准确率相同，直接报告相同；若某项原生组更省，也保留实测结果。这里比较包含既有转换实现的 R2G 整体能力。

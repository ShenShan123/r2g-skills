# R2G2.0 四阶段异构图数据集

本目录实现以预测时点为边界的四阶段数据集生成流程。每个样本生成
`floorplan`、`placement`、`cts` 和 `route` 四张异构图：

```text
G_stage = shared canonical base graph
        + features available before stage
        + shared post-route labels
```

四张图共享由 post-Yosys Verilog 建立的基础逻辑拓扑、Canonical 节点顺序和
Route 后标签。阶段间只允许特征值、特征有效掩码和符合输入时点的辅助边发生变化。

当前实现已经按 `bp_multi_top/v01` 完成四阶段回归并定版。B 视图中每类节点、边的
逐维英文定义、张量形状、单位、标签掩码和真实样本规模见
[B_VIEW_DATASET_STRUCTURE.md](B_VIEW_DATASET_STRUCTURE.md)。

## 1. 五个主脚本

工程只保留五个正式构建脚本：

| 脚本 | 职责 | 直接输入 | 默认输出 |
|---|---|---|---|
| `01_build_base_graph.py` | 从综合后 Verilog 建立固定逻辑拓扑 | JSON 配置、`yosys_v`、Liberty、`encode_map.csv`、raw manifest | `base_graph/base_graph.pt` |
| `02_extract_features.py` | 按四个因果截止点生成每阶段 8 张特征 CSV，并将阶段物理小网的 HPWL 聚合回 Canonical Net | base graph、合法阶段 DEF、Liberty、LEF、SDC、设计配置 | `stages/<stage>/features/` |
| `03_extract_labels.py` | 从 Route/post-route 数据统一生成监督标签 | base graph、Route DEF、LEF、SPEF、IR SP、Timing RPT | `labels/` |
| `04_assemble_heterograph.py` | 将共享拓扑、阶段特征和共享标签组装为 PyG 异构图 | base graph、8 张特征 CSV、共享标签 CSV | `stages/<stage>/heterograph.pt` |
| `05_build_stage_snapshots.py` | 生成相邻阶段变化和 base-to-stage Net lineage 审计快照 | base graph、Floorplan/Placement/CTS/Route DEF | `stage_snapshot.json`、`snapshots/*.json` |

`02_extract_features.py` 内置唯一一份 Canonical base Net 到后端物理 Net 的 lineage
算法。`03_extract_labels.py` 和 `05_build_stage_snapshots.py` 复用该实现，确保 HPWL、
Route 实际线长、RC 标签和快照使用同一种网络拆分对齐规则。

## 2. 四阶段因果边界

阶段名表示“接下来要预测的阶段”，不是输入文件自身的阶段名。

| 图数据集 | 输入截止点 | 允许读取的物理快照 | 标准 Gate 坐标可信 | Gate-Gate 几何边 |
|---|---|---|---|---|
| `floorplan` | post-Yosys | 不读取 DEF | 否 | 不建立 |
| `placement` | post-Floorplan | `2_floorplan.def` | 否；只信任宏和 IO | 不建立 |
| `cts` | post-Placement | `3_place.def` | 是 | 同格、无向、每点最多 5 邻居，边属性为中心欧氏距离 |
| `route` | post-CTS | `4_cts.def` | 是 | 同格、无向、每点最多 5 邻居，边属性为中心欧氏距离 |

`5_route.def`、post-route SPEF、PDNSim SP 和 post-route OpenSTA 报告只允许进入
`03_extract_labels.py`。它们不得参与任一阶段的特征提取。

所有阶段都组装同一套 Route 后标签。缺失值使用 `NaN`，对应 `*_valid` 为 `0`；
不能用数值 `0` 伪装缺失，也不能从后续阶段回填早期阶段。

## 3. 统一原始数据入口

五个脚本都通过同一个样本 JSON 的 `--config` 入口工作。配置中的相对路径以配置
文件所在目录为基准解析；例如 `encode_map.csv` 指向 `configs/encode_map.csv`，
`../generated/...` 指向工程根目录的 `generated/...`。

### 3.1 Raw 四阶段样本

统一根目录：

```text
/data/R2G2_dynamic_dataset/raw/v1/samples/<design_family>/<version>/
├── manifest.json
├── netlist/1_1_yosys.v
├── stages/
│   ├── 02_floorplan/2_floorplan.def
│   ├── 03_placement/3_place.def
│   ├── 04_cts/4_cts.def
│   └── 05_routing/5_route.def
└── parasitics/06_final/6_final.spef
```

配置字段映射：

| 配置字段 | 文件 | 用途 |
|---|---|---|
| `raw_sample_root` | 上述样本目录 | 来源描述；不会自动替代下面的显式路径 |
| `raw_manifest` | `manifest.json` | 输入语义和 SHA256 校验 |
| `yosys_v` | `netlist/1_1_yosys.v` | 唯一 base topology 来源 |
| `floorplan_def` | `2_floorplan.def` | Placement 预测输入；也用于快照 |
| `place_def` | `3_place.def` | CTS 预测输入；也用于 HPWL 和快照 |
| `cts_def` | `4_cts.def` | Route 预测输入；也用于快照 |
| `route_def`、`label_def` | `5_route.def` | Route 后线长、拥塞和 lineage 标签；不得用于特征 |
| `spef` | `parasitics/06_final/6_final.spef` | 正式 Cg、Cc、Reff 标签及 Timing 来源核验 |

修改新样本配置时，不能只修改 `raw_sample_root`；上述显式文件字段也必须同步修改。

### 3.2 Nangate45 公共工艺库

统一根目录：

```text
/data/R2G2_dynamic_dataset/technology/openroad-flow-scripts/flow/platforms/nangate45
```

主要使用：

```text
lib/NangateOpenCellLibrary_typical.lib
lib/fakeram45_*.lib
lef/NangateOpenCellLibrary.tech.lef
lef/NangateOpenCellLibrary.macro.mod.lef
lef/fakeram45_*.lef
config.mk
fastroute.tcl
```

- `lib` 配置标准单元 Liberty；存在宏单元时可通过 `yosys_hierarchy_lib_dir` 补充
  fakeram Liberty。
- `lef` 配置 tech/macro LEF；特征脚本还会从 `technology_root/lef` 自动发现
  `fakeram*.lef`，保证宏 Pin 几何完整。
- 2.1 um 拥塞网格来自 `15 fast-route tracks × 0.14 um Metal3 pitch`；Nangate45
  的 2000 DBU/um 下等于 4200 DBU。
- 工艺库保持全样本共享，不复制到每个生成目录；实际来源写入 provenance/SHA256。

### 3.3 Final 目录

统一目录结构：

```text
/data/R2G2_dynamic_dataset/final/<design_family>/<sample_id>/
├── 6_final.def
├── 6_final.gds
├── 6_final.sdc
```

当前正式配置主要从这里读取：

```text
sdc = /data/R2G2_dynamic_dataset/final/<design_family>/<sample_id>/6_final.sdc
```

`6_final.def` 和 GDS 不参与本工程的特征或标签构建。正式 Route 标签 DEF 使用 raw

### 3.4 IR-drop 输入

统一目录结构：

```text
/data/IRDrop_output/<sample_id>/
├── VDD_extracted.sp
├── VSS_extracted.sp
└── ir_drop.csv
```

配置字段：

```json
{
  "irdrop_sp": "/data/IRDrop_output/<sample_id>/VDD_extracted.sp",
  "irdrop_vss_sp": "/data/IRDrop_output/<sample_id>/VSS_extracted.sp",
  "irdrop_reference_csv": "/data/IRDrop_output/<sample_id>/ir_drop.csv"

```

- `VDD_extracted.sp` 是正式 IR-drop 标签源，由阶段三执行稀疏 KCL 求解。
- `VSS_extracted.sp` 当前保存为来源信息，不参与 VDD 压降计算。
- `ir_drop.csv` 仅用于交叉核验，禁止直接作为正式标签构图。

### 3.5 OpenRCX 输出

统一目录结构：

```text
/data/OpenRCX_output/<design_family>/<variant_id>/
├── ground_cap.csv
├── net_coupling.csv
└── pin_net_resistance.csv
```

可选配置：

```json
{
  "rc_label_dir": "/data/OpenRCX_output/<design_family>/<variant_id>",
  "rc_require_reference_match": false
}
```

这三张 CSV 只用于核验阶段三从同样本 raw SPEF 重新提取的 Cg/Cc/Reff。正式标签源
固定为 `spef`；`rc_source_mode` 必须为 `spef`，不能直接用 OpenRCX CSV 构图。

### 3.6 设计配置和 Timing 报告

工程还使用以下统一入口：

```text
/data/R2G2_dynamic_dataset/config_csv/<design_family>.csv
/data/R2G2_dynamic_dataset/time_rpt/<sample_id>/paths_max.rpt
/data/R2G2_dynamic_dataset/time_rpt/<sample_id>/paths_min.rpt
/data/R2G2_dynamic_dataset/time_rpt/<sample_id>/timing_manifest.json
```

- `design_config_csv` 提供运行该样本前已知的设计/流程参数。
- max/min RPT 提供 setup/hold 标签。
- 正式数据可用 `timing_manifest` 校验 RPT 与 Route DEF、SPEF、SDC 属于同一样本。

## 5. Base graph、Net 拆分和 IO-only Net

Base graph 的唯一拓扑来源是 `1_1_yosys.v`。Canonical 键固定为：

- Gate：`inst_name`
- Net：`net_name`
- IO Pin：`iopin_name`
- Pin：`(inst_name, pin_name)`
- Gate-Pin：`(inst_name, pin_name)`
- Pin-Net：`(inst_name, pin_name, net_name)`
- IO Pin-Net：`(iopin_name, net_name)`

只连接顶层 IO、没有内部 Gate incidence 的 Net 会显式加入 `base.net_names`，并记录
在 `io_only_net_names`；它仍可建立 IO Pin-Net 边，内部 `connection_rows` 为空是正常
情况。

Placement/CTS/Route 可能把宏多 Pin 大网拆成多条小网，也可能通过新增 BUF/INV 继续
分段。lineage 先用 `(inst_name, pin_name)` 和 `iopin_name` 直接锚定，再沿唯一归属的
新增透明 BUF/INV 分量扩展，最终把阶段小网聚合回原始 Canonical Net。基础拓扑永远
不因后端新增 Net 或 buffer 改写。

- CTS/Route 输入中的 HPWL：先遍历每条对齐物理小网的完整 DEF 端点（包含宏 Pin、
  物理常量单元和后端新增单元），分别计算小网 bbox 和 HPWL，再把所有小网 HPWL
  求和作为 Canonical Net 的 `hpwl_um`。`net_bbox_width/height` 表示所有小网 bbox
  的几何并集；禁止退回只遍历 base 端点的大网包围盒。
- Route 实际线长、Cg：对齐后按 Canonical Net 聚合 Route 小网标签。
- Cc/Reff：保存在独立 Net-Net、Pin-Pin 关系上，不合并进逻辑边 `edge_attr`。
- 若对齐存在多 Canonical Net 歧义，则 `lineage_valid=0`，不得强行聚合。

## 6. 特征、标签和辅助边契约

每个 `stages/<stage>/features/` 必须包含同表头、同 Canonical 行键顺序的 8 张 CSV：

1. `metadata.csv`
2. `nodes_gate.csv`
3. `nodes_net.csv`
4. `nodes_iopin.csv`
5. `nodes_pin.csv`
6. `edges_gate_pin.csv`
7. `edges_pin_net.csv`
8. `edges_iopin_net.csv`

Route 后标签只提取一次：

- `gate_con_IR.csv`：Gate congestion、IR-drop。
- `net_wirelength_Cg.csv`：Net routed wirelength、ground capacitance。
- `pin_timing.csv`、`iopin_timing.csv`：setup/hold slack。
- `edges_timing_path.csv`：可选 Timing Pin/IO-Pin 路径关系。
- `edges_net_net_Cc.csv`：独立 coupling-capacitance Net-Net 关系。
- `edges_pin_pin_Reff.csv`：独立 effective-resistance Pin-Pin 关系。

辅助关系必须独立保存：

- `gate|congestion_geom|gate`：仅 CTS/Route 图建立；2.1 um 同格、无向、每点最多
  5 个邻居，PyG 中用两个对称有向条目存储。分桶使用 Gate 放置原点，最近邻排序
  和一维 `edge_attr` 使用 Gate 中心欧氏距离 `euclidean_distance_um`；它不是标签。
- Timing path：按实际端点类型分别建立 Pin/IO-Pin 关系；端点节点不存在就丢弃该
  任务边，不创建 mapping/query 辅助数据。
- RC：Cc 使用 Net-Net，Reff 使用 Pin-Pin；对应节点不存在就不建立该关系。

Timing/RC 标签不能塞入原始逻辑视图或辅助关系的输入 `edge_attr`，只能放在独立
关系的 `edge_y` 与 `edge_y_mask`。某种视图缺少任务所需节点时，直接不构建该任务
及其标签边，不额外制造节点、映射文件或查询边。Gate-Gate 几何距离是可选输入特征，
仍然只存在于独立的 `gate|congestion_geom|gate` 关系中。

## 7. Snapshot 语义

每个 `stages/<stage>/stage_snapshot.json` 描述目标阶段完成后的变化，只用于审计或
未来的辅助监督，不是同目录预测图的输入：

| 图目录 | 快照比较 |
|---|---|
| `floorplan` | post-Yosys → Floorplan DEF |
| `placement` | Floorplan DEF → Placement DEF |
| `cts` | Placement DEF → CTS DEF |
| `route` | CTS DEF → Route DEF |

另外生成：

```text
snapshots/base_to_placement_snapshot.json
snapshots/base_to_route_snapshot.json
```

两张直达快照用于人工核查 Canonical 大网到 Placement/Route 小网的映射。HPWL 和
Route 标签提取不会等待 JSON：阶段二/三直接调用同一 lineage 函数完成反标，阶段五
结束后再把同一映射写成 JSON 审计产物，因此不存在流程循环依赖。

## 8. 运行顺序

工程不再保留额外的 `run_pipeline.py` 包装器，按编号执行即可。以 `bp_multi_top` 为例：

```bash
cd /data1/zhouzw/R2G2.0_dataset_full_4stage

python 01_build_base_graph.py --config configs/bp_multi_top_v01.json
python 02_extract_features.py --config configs/bp_multi_top_v01.json
python 03_extract_labels.py --config configs/bp_multi_top_v01.json
python 04_assemble_heterograph.py --config configs/bp_multi_top_v01.json
python 05_build_stage_snapshots.py --config configs/bp_multi_top_v01.json
python checks/validate_four_stage.py --config configs/bp_multi_top_v01.json
python checks/summarize_four_stage_graph_data.py \
  --root generated/bp_multi_top/v01
```
